Todos and pull requests, as plain files in your git repo.

todoer is one binary. Agents and people claim todos, work in git worktrees, and review the pull requests on the command line. No database, no server, no account.

Nothing to host. It is all in git.

A todo is a file in .todoer/todos/. Its name is its id. A pull request is a folder in .todoer/prs/, committed on the branch that it goes into. There is no settings file. A person and an agent can read every file, and git history keeps every change.

my-project/ .todoer/ todos/ prs/fix-the-login-crash/ labels/
.todoer/todos/fix-the-login-crash.md

A todo. The file name is its id and its title. todoer claim sets the assignee and commits the file, so you can push the claim at once. The front matter is optional.

---
assignee: you@example.com
labels: [auth]
---

Steps to reproduce: sign in with an expired token.
The app stops after the third retry.
.todoer/todos/add-rate-limiting.md

This todo waits for another one. todoer ls shows it as blocked while the other todo file exists. todoer done and todoer pr merge remove a todo file.

---
labels: [auth]
dependsOn: [fix-the-login-crash]
---

Limit the sign-in attempts for each account.
.todoer/prs/fix-the-login-crash/pr.md

The pull request. The folder name is its id and its title. pr.md holds the author, the branch of the work (from), the branch that it goes into (into), the base and the todos. -m of a later submit writes the ## Update section.

from: fix-login

.todoer/labels/auth.md

A label rule. The file name is the label. The text tells in plain words which todos must have the label. todoer does not read it: the agent reads the rules after todoer add and adds the labels.

Add this label to a todo that changes the login,
the sessions or the tokens.
Do not add it to a todo that only changes the docs.
.todoer/areas

The areas of the code. The patterns use the gitignore rules. The last pattern that matches a path wins. pr summary shows how many files and lines each area changes. -a security shows the diff of these areas only. -x e2e-tests,unit-tests hides them.

tests:       /tests
e2e-tests:   /tests/e2e

Plan the work, do the work, review the work.

plan3

A todo is a file with a name

add writes .todoer/todos/<name>.md. The text can come on stdin. done removes the file. check reports bad todos.

todoer add fix-the-login-crash -l auth

Dependencies, never a cycle

dep add refuses a cycle. A todo can wait for one todo or for all the todos of a label. ls --available lists the todos that can start now, and dep show prints the tree.

todoer dep add new-login-page -l auth-backend-refactor

Labels show the progress

A label groups related todos. progress lists them in dependency order. A label rule tells the agent in plain words which todos get the label.

$ todoer progress auth
auth  1/2 in progress (50%)  [#-]
work3

Any branch, your commits

todoer knows no main branch. claim commits the todo on your branch, so you can push it at once. Claim one todo, a list or a whole --label. A claim refuses a todo of another person or a blocked todo.

Agents work in worktrees

One command for the agent: pr submit --branch main squashes every commit since the work started from main into one, and commits the pull request on main. There is nothing to push and no hosting service.

One command makes it a skill

skill --init writes the workflow as a SKILL.md for Claude Code, Codex and Cursor. todoer skill prints it.

review3

A pull request is a patch

The pull request lands on your branch, so you review and merge it there. pr merge applies the patch and removes the pull request and its todos. On a conflict, nothing changes.

A merge is the approval

There is no approve and no verdict. A committed review asks for changes. pr submit --update replaces the patch and removes the review. pr merge stops while the review has a comment.

Code areas in the summary

Name the parts of the code in .todoer/areas, such as security or e2e-tests. pr summary shows how many files and lines each area changes. -a security shows only these files. -x unit-tests hides the tests.

From a todo to a merge.

You plan and decide. Agents claim, write the code, submit and update. Every step is a commit on your branch, so you can push it at any time.

$ cd ~/code/my-project
$ todoer skill --init
wrote .agents/skills/todoer/SKILL.md  (Codex, Cursor)
wrote .claude/skills/todoer/SKILL.md  (Claude Code, Cursor)
$ todoer add fix-the-login-crash -l auth "Steps to reproduce: ..."
.todoer/todos/fix-the-login-crash.md

Step by step, with what to tell your agent: read the guide.

  1. ClaimTell your agent: “claim fix-the-login-crash”, a list of todos, or a label. todoer claim assigns the todos to you and commits them on your branch. Push the commit when you want.
  2. Implement in a worktree“Implement it in a worktree.” The agent makes a new branch from your branch, writes the code and commits.
  3. Submit into your branchOne command: todoer pr submit --branch main. It squashes every commit since the work started from main into one, and commits the pull request on main. Name any branch.
  4. ReviewAsk another agent to explain the patch and to add your comments with todoer pr comment. Then commit the review.
  5. UpdateAsk an agent to do the comments. It restores the patch in a new worktree, so the first branch can be gone. Then it runs todoer pr submit --branch main -n <pr> --update, which replaces the patch and removes the review.
  6. Mergetodoer pr merge <pr>. There is no approve: a merge accepts the pull request. It stops while the review has comments.

Install

curl -fsSL sobanieca.github.io/todoer/install.sh | bash

The script installs todoer to /usr/local/bin, for all users. If that folder is not writable, the script stops with an error. Then run it with sudo:

curl -fsSL sobanieca.github.io/todoer/install.sh | sudo bash

Or pick your own folder with INSTALL_DIR. It must be a folder on your PATH:

curl -fsSL sobanieca.github.io/todoer/install.sh | INSTALL_DIR=~/.local/bin bash

A single binary for Linux and macOS (x64 and arm64), no runtime needed. Update it any time with todoer update. Run todoer help to see every command. todoer is not released yet: until version 1.0.0, any part of it can change.
